## What is observed

The marker is `PAGURA_N16_REACH_V1 `. Records appear in source traversal order:

- `plan`: after actual precision selection and the nonopaque-background guard;
  records requested mode, whether the Competitive policy is executing, actual
  format/side, requested tile, and background bytes. One full render must have
  exactly one plan record; a second plan or wrong Competitive flag exposes an
  unexpected retry/fallback and blocks this scoped reach claim.
- `chunk`: actual render_chunk region and admitted format, before any bypass.
- `bypass route=opaque-image`: the real image shortcut returned successfully;
  this is not evidence of N16/F32 page stores.
- `surface`: successful page surface format and existing byte ledger.
- `writer`: an N16 path span or fragment row, after its existing destination/
  clip checks and interval update, immediately before the unchanged infallible
  store. These report submitted ranges, including zero-coverage data. No scan
  of pixels or reconstructed coverage is introduced.
- `output`: actual N16 interval and the sum of pixels/calls passed to
  Buffer::output by the existing row intersections. F32/U8 report dense output
  pixels. F64 reports visited pixels, not a claim every pixel was converted or
  stored (transparent values can be skipped).

The example retains its existing six arguments; a temporary seventh argument
`R,G,B,A` sets the public RenderOptions background for one explicit control.
All other calls and ordinary fixture bytes are unchanged. Its stage timings
must be retained only as raw diagnostic output, never analyzed as performance.
